# 小笼洛包

基于本地大语言模型（Ollama）的智能聊天软件，支持文字 / 语音对话、联网搜索、语音合成（GPT-SoVITS）、
B 站点歌、角色与语音预设管理、对话记录保存等功能。输入输出界面已统一集成到 **Web UI**。

项目演示视频链接：

## 快速开始

### 一键启动（推荐）

双击 **`启动.vbs`**（完全不出现命令行窗口），或双击 `start.bat`，也可以在命令行运行：

```bash
venv\Scripts\pythonw.exe launcher_gui.py        # 图形启动器（无控制台）
venv\Scripts\python.exe launcher.py            # 控制台版（可看完整输出）
```

图形启动器会直接打开启动界面，在其中选择运行模式（点击即按该模式拉起服务，然后进入正式界面）：

1. **Lite 模式**：仅加载语音合成（GPT-SoVITS），大模型只能使用外部 API
   （不启动 Ollama、不加载 Whisper），启动最快；
2. **标准模式**：启动全部本地服务（Ollama + GPT-SoVITS，Whisper 后台加载）。

控制台版 `launcher.py` 的交互方式（供排查问题使用）：

1. **界面方式**：
   - `1. 桌面版`：内嵌窗口显示界面（推荐；需已安装 pywebview，
     安装命令：`venv\Scripts\python.exe -m pip install pywebview`，未安装时自动改用浏览器）；
   - `2. 网页版`：使用浏览器打开界面。
2. **运行模式**：
   - `1. Lite 模式`：仅加载语音合成（GPT-SoVITS），大模型只能使用外部 API
     （不启动 Ollama、不加载 Whisper）；
   - `2. 标准模式`：启动全部服务（Ollama + GPT-SoVITS + Whisper）。

桌面版会等待 Web 服务就绪后再打开窗口；端口被占用时自动顺延，窗口始终指向
实际可用地址，不会出现"无法访问"的情况。

图形启动器（`启动.vbs` / `start.bat`）不出现命令行窗口：它用 `pythonw.exe` 运行，
所有输出写入 `runtime/logs/launcher_gui.log`（语音合成 / Ollama 等子进程也静默启动，
不会弹出命令行窗口）；启动界面上直接点 Lite 或 标准 即可，服务拉起后同一个窗口进入
对话界面。**每次启动都会显示这两个选项**（已经启动过也可以重新选择模式）。
对话界面在合成语音时，会用一条细横线进度条占据「重播」按钮的位置，合成完成后自动换成按钮；
**关闭窗口就是完全关闭程序**（停止语音合成 / Ollama 并结束后台进程，仅在图形启动器模式下生效）。
代码更新后再次启动时，若端口上还挂着旧版本后台，启动器会自动结束它并启动新版本（不会出现「改了代码界面还是旧的」）。
点窗口右上角 X 直接关闭：程序**以窗口进程退出为检查点**（不依赖页面脚本），立刻卸载模型权重、停止语音合成（含上一次运行遗留的进程）与 Ollama，再做记忆库收尾与缓存清理，最后复核进程与端口都已释放；全过程写入 runtime/logs/xiaolongluo.log（含显存占用前后对比），并有 30 秒硬超时兜底。

> 首次使用请先编辑 `launcher_config.json`，把 `gpt_sovits.api_script` 改成你自己的
> `api_v2.py` 路径（默认已填入示例路径），并按需调整端口 / 地址。

### 仅启动 Web（服务已手动运行时）

```bash
venv\Scripts\python.exe app.py
venv\Scripts\python.exe app.py --port 9000
```

### 安装依赖

```bash
venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 使用说明

界面顶部可切换两种模式：

- **问答模式**：输入文字或点击 🎤 单次录音（静音自动停止）。
- **实时模式**：点击麦克风按钮后连续聆听，逐句对话；说“退出”结束、“暂停”暂停、“继续”恢复。

顶部的「设置」是**唯一**的设置入口，进入后左侧是分类标签、右侧是该分类的具体内容：

- **通用设置**：音量（对话 / 音乐）、影响力范围、联网开关、调试模式、Tavily 额度；
- **角色与语音**：**每个角色一张卡片**——勾选即参与多人对话、按分类展开查看设定（自定义要求 / 参考资料 /
  完整提示词）、设置该角色在多人对话中的声线；卡片右侧提供「设为当前 / 修改设定 / LLM 优化」，
  还有「新建角色」；语音预设（单人对话音色）在同一标签内；
- **对话记录**：查看 / 标记 / 保存 / 清空；
- **插件管理**：只负责插件的启用 / 停用与重新加载；
- **插件设置**（每个插件一个标签，左侧栏有分隔线 + 标题右侧「插件」标记）：该插件的全部参数、快捷操作与运行状态。

对话记录上方常驻一个**状态胶囊**（标题栏下方靠左）：正在聆听 / 识别 / 生成回复 / 合成播报 /
多人对话生成 / 音乐准备与播放 / 暂停等**持续性状态**都在这里显示，空闲时显示「就绪」；
清空上下文、跳过、下载失败这类**一次性提示**仍然写进聊天记录，不会被漏看。
音乐播放条带可拖动进度条（点击 / 拖动 / 左右方向键跳转），支持暂停与停止。

> 旧的角色管理页面 `/characters.html` 已合并进「角色与语音」，访问旧地址会自动跳转到设置页。
> 相同的设置只保留一种方式（原先重复的「当前角色 / 自定义角色」表单已移除，统一改为角色卡片）。
> 记忆管理也不再单独开页面：由「上下文记忆库 → 查看 / 管理记忆」在当前界面上弹出大号浮层窗口
> （旧地址 `/memory_view.html` 会自动跳转）。插件可通过动作返回 `{"modal": "名字"}` 打开
> 注册在 `window.XLLB_MODALS` 的浮层，这是插件贡献「浮层窗口」的统一入口。

### 角色设定的修改与优化

- **修改设定**：卡片上的「修改设定」可编辑该角色的提示词（自定义要求 / 参考资料 / 提示词全文）；
  只改「自定义要求 / 参考资料」时会按历史格式重建提示词，保证改动真的会影响实际发给模型的设定；
- **LLM 优化**：卡片上的「LLM 优化」把当前提示词交给大模型整理（去掉网页残留、归纳为身份 / 性格 /
  说话风格 / 关系 / 禁忌等条目），结果填入对话框供你检查后再保存；
- **联网搜索补全设定**：对话框内的显眼按钮，用 Tavily 抓取角色资料并填入「参考资料」（消耗 1 次额度）；
- **新建角色**：手填或用上面的联网搜索补全，保存后即可在卡片里勾选参与多人对话；
- 保存角色设定属于危险写操作：客户端标识 + 一次性确认令牌（`characters.preset` / `characters.create`）。

### 多人对话的「可用性握手」

多人对话能力由「多人对话」插件自己声明是否可用（`available(ctx)`），设置页据此决定输出方式：

- 插件**未启用** → 角色勾选区只读，界面明确提示「单人输出」，并提供一键跳到插件管理的入口；
- 插件已启用但**勾选不足 2 个角色** → 仍是单人输出，界面给出原因（已选 N 个，至少需要 2 个）；
- 勾选满 2 个角色 → 插件声明可用，界面显示「多人对话：已激活」，对话按多角色输出。

保存勾选同样走安全约束：必须带客户端标识、必须携带服务端签发的一次性确认令牌，
且插件未启用 / 正在重载时直接拒绝（409 并说明原因）。

### 界面风格

- **统一字体与控件**：全站同一套中文字体栈，输入框 / 下拉框 / 按钮都继承字体；字号、圆角、控件高度收敛为
  统一的刻度变量（`--fs-*` / `--radius-*` / `--ctl-h`），所有二级页面共用同一套
  页面骨架（`.page` / `.page-inner`）与控件样式（`.input` / `.select` / `.textarea`）。
- **图标与文字统一**：界面不使用表情符号，按钮图标为同一套内联 SVG（24×24 视图框、1.7 线宽、
  继承文字颜色、统一渲染 18×18），标题 / 说明 / 正文分别使用 `--fs-lg` / `--fs-sm` / `--fs-base`。
- **长列表性能**：记忆管理页与插件列表改用「服务端分页 + 按需追加」，条目使用
  `content-visibility: auto`，且列表卡片不再叠加背景模糊（每个卡片一个模糊层会让滚动明显掉帧）。
- **跟随「背景设置」主题**：浅色 / 深色 / 自定义图片三种主题对所有页面生效；主题脚本直接注入在 `<body>`
  起始处，页面第一帧就是配置的主题（不会先闪一下默认深色）；自定义图片模式下各面板用半透明底色让背景图透出来，
  同时不做大面积毛玻璃模糊，保证滚动流畅。
- **背景图缓存**：`/api/background/image` 带 `ETag`，浏览器命中缓存返回 304，切换页面不会重复下载整张图。

点歌：直接说“播放 晴天”“来一首 想见你”等，从列表中选择即可播放；
“暂停音乐 / 继续音乐 / 停止音乐”可控制播放。

### 播放与缓存

- **流式语音播放**：回复语音按句流式合成，第一句生成后即开始播放，后续句子边生成边播放，降低等待感。
- **实时模式与音乐**：音乐播放期间彻底禁用语音识别（避免拾取音乐声与音频设备抢占），音乐播放结束后自动恢复。
- **缓存自动清理**：合成语音与临时音乐存放在 `runtime/`，程序退出时自动清空，运行中也会定期清理过期文件。

### 语音合成服务（GPT-SoVITS）启动与排错

- **端口自动选择**：默认端口 9880 在部分 Windows 机器上会落在「系统保留 / 排除」段
  （Hyper-V / WSL / Docker 预留，可用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看），
  此时 GPT-SoVITS 加载完模型后会因 bind 失败（WSAEACCES 10013）立刻退出——看起来就是「自己关闭」。
  程序启动前会检测端口可监听性，不可用就自动改用可用端口（如 20000），并把结果写回
  `launcher_config.json` 的 `gpt_sovits.port`（同时更新 `api_url`），保证监听与访问一致；
- **日志不再丢失**：GPT-SoVITS 的输出写入 `runtime/logs/gpt_sovits_api.log`，
  启动后立刻退出时会自动读日志尾部并给出原因（端口被占用 / 保留、CUDA 初始化失败等）；
- **界面可见、可一键重启**：「设置 → 角色与语音 → 语音服务」显示就绪状态、实际端口、进程号与上次失败原因，
  可点「重启语音服务」（无需重启整个程序）；
- **诊断**：`setup\诊断.bat` 会检查端口是否可监听，并给出 `gpt_sovits.port` 的修改建议。

## 插件系统

`plugins/` 目录下的每个 `.py` 文件都是一个插件，支持**热加载**（无需重启）：

- 在 Web UI 的「⚙️ 设置 → 插件管理」中查看、启用 / 停用插件（每个插件的参数在左侧自己的标签里填写），
  点“重新加载插件”即可让新增 / 修改的插件生效——**只有内容变化的插件会被重载**，
  未变化的插件不会被卸载重建（因此不会影响记忆引擎、会话上下文与后台线程）；
- 插件可声明**设置表单**（在 UI 中直接填写并保存）、可拦截 / 改写每一次大模型调用（`pre_llm` / `post_llm`）；
- 停用 / 重载插件时可通过 `ctx.unload_reason`（`"disable"` / `"reload"`）区分处理；
  可用 `RELOAD_POLICY` 声明重载语义（是否保留上下文、是否允许对话中重载）；
- 第三方开发者把插件文件放进 `plugins/` 即可扩展功能，详见 `plugins/README.md`。

内置插件（在 UI 中以「官方 / 第三方」标注区分）：

## 上下文记忆（长期记忆）

启用「上下文记忆库」插件后，对话会被自动整理成长期记忆，供以后随时回忆（毫秒级检索）：

- **只记住有意义的内容**：问候、寒暄、语气应答等低信息量回合自动跳过归档（可在插件设置中开启 LLM 深度复核）；
  归档以**用户输入**为核心，角色回复仅作补充检索词；
- **按时间回忆**：直接问“昨天/上周三/去年冬天/今年 Q2 我们做了什么”等，相对时间词按当前时间自动翻译；
- **上下文感知**：话题切换不残留旧内容（如聊完“酸菜鱼做法”再问“新歌推荐”不会串味）；
  省略式追问（“那周六呢”“然后呢”）自动衔接上一轮；
- **防止错答**：检索/联网内容与当前话题无关时自动阻止注入；新闻/天气等实时信息按需自动联网搜索；
- **记忆管理页**：在插件「高级选项」→「查看 / 管理记忆」打开，按层级（L0/L1/L2/L3）查看、
  关键词/日期查询，并可手动新增 / 编辑 / 删除记忆（严格标准格式校验）；
- **存储有界**：季度滚动归档 + 按季度/年度聚合 + 原文压缩，数据只降级、绝不删除；
  长时间未活动会自动清理残留上下文；「高级选项 → 记忆初始化」可一键清空全部记忆（二级确认 + 服务端一次性令牌）。

### 记忆服务门禁（插件停用 / 只读模式的强制边界）

所有记忆访问（核心对话检索与写入、插件、Web 管理接口）都经过 `memory_engine/service.py` 这一处门禁，
不再各自 `get_engine()` 隐式初始化：

- **引擎默认只读**：写入必须显式 `set_mode("readwrite")` 或由记忆插件启用后下发；
  `get_engine()` 默认**不初始化**（不隐式打开 / 写库）；
- **停用插件 = 立即停止检索与写入**：核心对话路径拿到的是「不可用」，既不检索也不归档，
  连 L0 临时上下文都不再写入；停用**不关闭引擎、不清空 L0**，再次启用可无缝恢复、不丢上下文；
- **访问分级**：`read`（查看/检索，只读模式允许）、`turn`（记录回合，只写 L0 会话上下文，只读模式允许）、
  `write`（归档到长期记忆，仅完整权限）、`manage`（人工增删改 / 初始化，仅完整权限 + 管理权限位）；
  拒绝时返回中文原因与当前模式，Web 接口用 409 明确告知，不让用户误以为设置已生效；
- **会话代次**：清空对话 / 记忆初始化会递增代次并丢弃待归档任务，
  避免「刚清空对话，后台旧任务又把旧回合写回长期记忆」；
- **数据目录隔离**：`active` / `archive` / `cold` / 日志 / FTS 标记全部由实例的 `data_dir` 推导，
  单例复用路径不一致时直接报错（测试数据不会写进真实 runtime）。

### 生命周期与退出

- **插件重载是增量的**：只有文件内容变化的插件才会被卸载重载，未变化的插件完全不碰；
  重载前会静默该插件并等待在途调用结束；记忆插件重载保持引擎实例与 L0 会话上下文；
- **后台治理线程有明确状态机**（`running` / `stopping` / `stopped` / `failed` 等），
  停用时会 join 线程，快速启停不会再出现「没有维护线程」；
- **统一退出流程**（`core/shutdown.py`）：停止接受新请求 → 停止新归档 → 等待归档队列排空 →
  关闭记忆引擎与数据库 → 停止 TTS 流式任务 → 清理临时文件，并输出每一步耗时报告；
  不再只依赖 daemon 线程自动结束。

### 模型与自动调优

支持两种大模型后端（Ollama / OpenAI 兼容 API），**生成模型与判断模型的后端、模型名均可分别设置**：

- **Ollama（本地）**：模型下拉框会**列出已安装的 Ollama 模型**供选择（如 `qwen3.5:9b`、`qwen3.5:2b`）；
- **OpenAI 兼容 API**：填 API Base URL 与 Key（或读环境变量 `OPENAI_API_KEY`），即可用任意兼容服务；
- **一键自动调优**：检测显存 / 内存 / CPU，自动推荐并应用合适的模型配置（显存不足时提示改用更小模型或 API）；
- **省显存**：当生成模型与判断模型相同时，Ollama 只会加载一次模型权重（`/model` 会提示“仅加载一次”）。

也可用命令：`/model <模型名>`、`/judge <模型名>`、`/backend ollama|openai`、`/jbackend ollama|openai`、`/autotune [apply]`、`/sysinfo`。

### 前置依赖

- **Ollama**：本地大模型服务，默认模型 `qwen3.5:9b`（在 `core/config.py` 修改 `OLLAMA_MODEL`）。
- **GPT-SoVITS API**：语音合成服务（`launcher_config.json` 配置 `api_script`，默认端口 9880）。
- **Whisper 模型**：`models/whisper` 下的 faster-whisper 模型文件。
- **ffmpeg**：点歌下载转码需要（路径见 `core/config.py` 的 `FFMPEG_PATH`）。
- **pyarrow（可选）**：上下文记忆库 L3 冷存储原文使用 Parquet 格式（更高效、省空间）；
  未安装时自动降级为 JSONL，**功能完全不受影响**。安装：`venv\Scripts\python.exe -m pip install -r requirements.txt`
  （启动预检与「诊断.bat」会提示该可选依赖是否就绪）。

### 接口加固（确认令牌 + 防跨站）

- 所有 `POST` 必须带自定义请求头 `X-XLLB-Client: <客户端 id>`（缺失 → 403）；
  带 `Origin` 且与 `Host` 不同源 → 403（自定义头 + 同源校验可挡住跨站表单 / 第三方脚本）；
- **危险操作改为服务端两步确认**：先 `POST /api/confirm/prepare` 领一次性令牌
  （`secrets` 随机、绑定操作类型 / 目标 / 客户端、120 秒过期、用后即废），
  第二步请求带 `token` 才执行；覆盖：清空对话、删除记忆、插件重载 / 启停、二次确认类插件动作、
  含模型与 API Key 的插件设置保存。缺少或失效令牌返回 409 且带 `need_confirm: true`；
- 记忆管理接口统一走记忆门禁，被拒时返回 409 并带 `plugin_enabled / mode / level / reason`
  等字段，前端据此如实提示「插件未启用 / 只读模式」；
- 这套机制用于防止「绕过界面确认」与「跨站请求」，**不是用户认证**：
  单机应用默认信任本机请求，接入账号体系时在 `web/server.py` 的 `_authorize()` 中校验即可全链路生效。

## 配置需求
- **最低配置**：仅部署本地语音合成，需求判断与生成回复采用外接API
- GPU推理：4G显存（GTX 1060以上），8GB以上内存，硬盘空间大于20GB（程序16GB左右，但要为运行时的临时文件预留4GB）
- 无独立显卡：4核心8线程cpu，16GB内存，硬盘空间大于20GB（非常不推荐，极易造成崩溃）
- ps：非常极限，容易造成程序崩溃或其他未知错误，强烈建议使用更高配置

  
- **推荐配置**：完全使用本地部署方案（以9b大小的q4量化模型为基准）
- 12G显存以上（RTX 3060以上），16GB以上内存，硬盘空间大于20GB
- ps：不建议使用小于9b的模型作为生成回复的底模，模型幻觉会比较严重，9b实测算是推理速度与质量的一个甜点
  
## 常见问题

- **语音合成失败**：确认 GPT-SoVITS API 已启动（看 `launcher_config.json` 的 `api_script` 是否正确），
  且 `voice_presets` 中的参考音频路径正确。
- **语音识别失败**：确认 `models/whisper` 模型完整，浏览器已授权麦克风。
- **联网搜索失败**：检查 `core/config.py` 的 `TAVILY_API_KEY` 与额度。
- **点歌下载失败**：确认 `ffmpeg` 路径正确且网络可访问 B 站。
